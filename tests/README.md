# Tests

The interesting thing here is that **the UI can be read as text**, so layout
changes can be tested — and reviewed — without opening a window.

## Seeing the UI

```sh
cargo run --bin layout_dump
```

That prints the resolved workspace layout as a box diagram, a dock legend,
and an explicit border list. It's generated by
`larkspur::ui::introspect`, which resolves `ui::layout::app_layout()`
(the single definition of the layout, also used by the real UI) into
rectangles — no GPUI, no `App`, no `Entity`.

The output looks like:

## Writing layout tests

Two entry points, both in `larkspur::ui`:

- `layout::describe_app() -> String` — the diagram above, for snapshots and
  human/LLM review.
- `introspect::report(&LayoutPlan, &ModuleSizes) -> LayoutReport` — the same
  information as **structured data** (`regions`, `borders`, `docks`). Assert
  against this rather than parsing the diagram.

`tests/layout.rs` is the worked example:

```rust
let report = introspect::report(&layout::app_layout(), &layout::module_sizes());
assert!(touches(&report, "playback", "empty-left")); // bar meets the left rail
```

`ModuleSizes` supplies intrinsic sizes for fixed-size modules (the 240px
cover, the transport bar) so `Fit` bands in the diagram aren't drawn as
slivers. If you add a fixed-size panel, add it to `layout::module_sizes()`.

## Adding tests

- **Pure model logic** (LRC parsing, cover-cache byte budget, song-id
  hashing, extension checks) — unit tests live next to the code in
  `src/model/*.rs`.
- **Layout / structure** — add to `tests/layout.rs` using the report above.
- **Decode/seek behaviour** — there's no audio fixture in-repo; use
  `cargo run --bin seek_probe -- <file>` against a real file.

## Conventions

- Tests never open a window and never need an audio device.
- Prefer asserting on structured data (`LayoutReport`) over string matching;
  use the text form for readability and diagnostics.
